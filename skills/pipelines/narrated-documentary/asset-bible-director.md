# Asset Bible Director - Narrated Documentary Pipeline

## When To Use

The segment plan exists. Before generating any AI video, build the Asset Bible:
one canonical reference image per recurring location/subject. Every AI shot of
that asset is later generated by image-to-video FROM this single reference, so
the location/subject looks the same across the whole documentary. This is the
mechanism that prevents the "same hospital is a different hospital every scene"
drift that AI video is prone to.

## Prerequisites

| Resource | Purpose |
|----------|---------|
| Schema `schemas/artifacts/asset_bible.schema.json` | Artifact validation |
| Prior artifact `segment_plan` | Segments + their location_id / subject_continuity |
| Tool `image_selector` (-> `nano_banana_image`) | Generate canonical reference images |
| Lib `lib/asset_bible.py` | `extract_assets`, `validate_referential_integrity`, `build_prompt_anchor` |
| Script `build_asset_bible.py` | Extract assets + generate canonical images |

## What This Stage Does

1. **Extract recurring assets** from the script: one LOCATION asset per distinct
   `location_id`, one SUBJECT asset per `subject_continuity` chain. One-off shots
   that never recur get no asset (they're generated fresh).
2. **Lock identity:** each asset carries `locked_attributes` (period, materials,
   palette, signature details) + `period_constraints` that are injected into
   EVERY shot's prompt via `build_prompt_anchor`.
3. **Generate one canonical reference image** per asset (Nano Banana 2), saved to
   `assets/asset_bible/<asset_id>.png`.
4. **Validate referential integrity:** every `asset_ref` in the script resolves;
   every canonical image exists.

## Workflow

```
python projects/<project>/script_v5/build_asset_bible.py --dry-run   # review the asset list first
python projects/<project>/script_v5/build_asset_bible.py             # generate canonical images
```

1. Run `--dry-run` to see the extracted assets and edit `locked_attributes` /
   `period_constraints` / `description` for period accuracy before spending.
2. Run for real to generate the canonical images (Nano Banana 2).
3. Confirm referential integrity passes (the script prints errors if an
   `asset_ref` doesn't resolve or a canonical image is missing).

## Quality Bar

- Exactly one canonical reference image per recurring asset
- Locked attributes are period-accurate (e.g. "1985 era - CRT only, no LED")
- Referential integrity passes (every `asset_ref` resolves; images exist on disk)
- The canonical image actually looks like the described place/subject

## Ethics

Do NOT create AI canonical images of real, identifiable historical people. Asset
Bible entries are for places, equipment, and anonymous/illustrative subjects.
Real people and real events belong in archival footage.

## Common Mistakes

- **Generating images before reviewing the asset list.** Use `--dry-run` first;
  fix the locked attributes, then spend.
- **One canonical image for two different places.** If two `location_id`s are
  genuinely different locations, they must be distinct assets (distinct images),
  even if they're the same kind of room.
- **Vague locked attributes.** "hospital" drifts; "1985 corridor, beige speckled
  linoleum, pale green walls, fluorescent tubes, no modern signage" holds.
